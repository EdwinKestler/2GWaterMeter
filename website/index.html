A household water meter that learns its own usage fingerprint.

Pulse counting on an ATmega644PA, MQTT over 2G, a two-harmonic daily model fitted in the cloud and evaluated back on the MCU. Night leak and daytime overuse are flags the device sets itself.

The loop closes on the device: the cloud never commands a valve on a model result, it only returns coefficients.

01 · device
Count and publish

Hall pulses on D6 via digitalPinToInterrupt. tl_ml, valve state and RSSI go out on waterbox/<IMEI>/data, then the radio shuts down.

02 · cloud
Fit W(t)

Python least-squares over historical flow: mean + 24 h sine + 12 h sine. Hourly, per IMEI, written to fingerprints.

03 · device
Evaluate onboard

Coefficients return retained on …/fp. The MCU compares live flow against W(t) and sets lk and oc.

04 · people
Portal and ops

Households get litres, overlay and map on :3001. Grafana on :3000 stays an operator tool. Latching valve shutoff is optional.
