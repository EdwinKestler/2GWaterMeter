firmware/waterbox

Object-oriented FSM on the Core+

Pulses are counted in an ISR at all times. The radio comes up about every 60 s to publish, then listens 8 s for valve commands and fingerprint updates, then shuts GPRS.

Modules

ClassRole
FlowMeterD6 ISR, 32-bit pulse total, L/min (245 or 490 p/L)
LatchingValveL9110 25 ms open/close
MeterStoreEEPROM: pulses, valve, fingerprint + CRC
GsmMqttClientSIM800 + MQTT; subscribe cmd/fp; publish data/info/hb
ConsumptionSignatureEvaluate W(t); set lk / oc
WaterboxFsmHaltAuth → WaitModem → Idle → Connect → Publish → Listen → Disconnect

MQTT (per IMEI)

TopicDirPayload
waterbox/<IMEI>/dataoutlm, mls, tl_ml, ts, v, wm, lk, oc
waterbox/<IMEI>/infooutppl, reed, v, fp
waterbox/<IMEI>/hbouthourly health: up, rssi, ok, valve, totals
waterbox/<IMEI>/cmdinon / open / 1 or off / close / 0 or {"v":1}
waterbox/<IMEI>/fpinretained fingerprint JSON w,a1,p1,a2,p2,t1,t2

Commands and fingerprints only arrive during the 8 s listen window. Keep fp retained on the broker. Lab MQTT user/pass: waterbox / waterbox. Set mqttServer to the LAN IP of the Compose host — not localhost.

Lab clock

This Core+ is 8 MHz (actual UART was half of 57600 when built as 16 MHz). PlatformIO board is 644pa8m, upload and serial both 57600.
