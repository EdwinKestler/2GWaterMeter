3. MQTT message flow

RabbitMQ MQTT plugin · port 1883
Topics are per IMEI · radio up ~8 s after each publish

Device session

1 ConnectTCP + MQTT auth · client id = IMEI
↓
2 Subscribecmd and fp
↓
3 Publishinfo then data
↓
4 Listen 8 sCMD_LISTEN_MS
↓
5 DisconnectCIPCLOSE + CIPSHUT

Device → broker

waterbox/<IMEI>/data fields: imei, lm, mls, tl_ml, ts, v, wm, lk, oc
waterbox/<IMEI>/info fields: imei, ppl, reed, v, fp

Broker → device (only during listen window)

waterbox/<IMEI>/cmd exact payload on or off → latching valve
waterbox/<IMEI>/fp fields: w, a1, p1, a2, p2, t1, t2 · retained

Cloud worker subscriptions

waterbox/+/datainsert readings + wm_cloud
waterbox/+/infoupsert meters
publish …/fp retain=trueafter each successful fit

Timing

PUBLISH_INTERVAL_MS = 60 sGPRS down between cycles · pulses still counted
CMD_LISTEN_MS = 8 scmd and fp must arrive in this window (fp is retained)
AuthmqttUser / mqttPass waterbox · MQTT_ALLOW_ANONYMOUS 0
