Technical explanation · MIT Solve / Empagua

A household water meter that learns a usage fingerprint and flags leaks.

Open hardware + 2G MQTT + Postgres. The cloud fits a two-harmonic daily model; the meter evaluates it onboard. Households see their own litres, map, and signature. Operators keep Grafana.

1. IoT data

The Core+ counts Hall pulses, publishes litres and valve state over SIM800 MQTT every 60 s, then listens 8 s for commands.

2. Cloud model

Python least-squares fits W(t) = mean + 24 h sine + 12 h sine on historical flow.

3. Live compare

Coefficients return on …/fp. The MCU flags night leak and daytime overuse.

4. Leads

Household portal charts and map; Grafana for the operator; optional latching-valve shutoff.

What this site covers

Hardware

RPE body, latching coil, Microduino Core+, SIM800, enclosure photos and CAD.

Firmware

FSM, D6 interrupt, per-IMEI MQTT, valve cmd, hourly heartbeat.

Cloud

RabbitMQ MQTT, one Postgres, worker, Grafana, Compose lab stack.

Household portal

IMEI login, consumption graphs, fingerprint overlay, OSM geofence map.

This is a 2016-era 2G prototype (Tigo Guatemala / Empagua). It is a lab system today. 2G sunset and a radio revision are documented under Goal.
